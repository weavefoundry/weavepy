# Preserve unassigned locals on native exits

This candidate fixes a confirmed preexisting local-binding defect. Earlier JIT binaries exposed default buffer values, including zero, None, or an unrelated function, in locals whose assignments had not executed. The candidate records path-specific assignment flags and preserves original interpreter objects until assignment. Frameless calls retain their checked parameter values and leave unwritten later locals unbound. Flags persist through native generator suspension and are recycled with their owning buffers.

The change adds disjoint per-local u32 storage to JitFrame and updates its unsafe entry contract and every workspace caller. Lowering tracks assignments through branches, loops, helper boundaries, and shared terminal exits. No guards, eligibility thresholds, or callback behavior are removed, and completed calls are not replayed. The six changed source files and all 340 exact build inputs are preserved.

Validation passed: 67 compiler tests, 351 VM tests, 156 C API tests, strict compiler/runtime lints, formatting, the no-JIT check, 99 targeted runtime checks, 44 native-path expectations, and all 275 compatibility cases. New compiler tests verify conditional assignment flags at a common exit, zero/nonzero loops with OSR, and persistence across native generator resume.

All 14 Python state cases match CPython for the candidate in JIT, interpreter, and GIL-disabled correctness modes. The preceding phase 83 JIT differs in eight. Six functions have native compilation and reconstruction evidence; the overwritten-argument and generator exception cases are controls without native-exit evidence. Existing generator materialization and lifetime tests also pass. The known native frame-identity/mid-call locals limitations are not claimed fixed.

The first native validation stopped at a strict Clippy iterator-style diagnostic after its VM and C API tests passed. Source version 02 corrects that loop and passes the complete repeated validation. The first Python oracle could not serialize an unexpected function exposed by the baseline; its second version changes only diagnostic serialization. Both original failures and every corrected run are retained.

The complete 24-fixture coverage audit uses authoritative work values, unchanged function definitions, one cold invocation, and a result footer instead of the original timer. Every result matches CPython: integers compare exactly in hexadecimal and finite floats use relative and absolute tolerances of 1e-12. Full traces, rejection reasons, counters, wrappers, sources, and cache identities are retained. The first audit logged nine matching rows before pidigits exceeded CPython's decimal repr limit; the corrected audit changes only integer transport and preserves that earlier failure.

The audit confirms compilation barriers in generic indexing for deque_ops/list_ops, mixed arithmetic in datetime_ops, loop shape in pickle_bench, dictionary deletion in dict_ops, and type inference in nbody._advance. A separate comprehension probe agreed with CPython but was rejected as TypeUnknown by every JIT variant; it does not establish native cleanup behavior.

Performance has not been measured for this correctness candidate. The executable is 44,098,064 bytes, 32 bytes larger than phase 83. Two native call helpers reserve 32 more stack bytes each; compiler and dynamic helper prologues are unchanged. These are static reservations, not total stack use or peak RSS. Runtime timing, CPU, and memory effects remain outstanding. The last measured cumulative phase 83 result remains about 3.31 times CPython workload time and 2.01 times peak RSS. The overall performance goal is unachieved.

The primary runtime remains unchanged. This archive preserves a validated correctness candidate for subsequent performance work; it does not claim broad performance superiority or silently substitute its untimed results into a measured comparison.
